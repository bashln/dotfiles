## Objective

Triage issues in the current repo using a label-based state machine. Infer the repo from `git remote`. Use `gh` for all GitHub operations.

## AI Disclaimer

Every comment or issue posted to GitHub during triage must include at the top:
```
> *This was generated by AI during triage.*
```

## Reference docs

Reference files in this skill directory: `AGENT-BRIEF.md`, `OUT-OF-SCOPE.md`.

## Labels

| Label | Type | Description |
| ----- | ---- | ----------- |
| `bug` | Category | Something is broken |
| `enhancement` | Category | New feature or improvement |
| `needs-triage` | State | Maintainer needs to evaluate |
| `needs-info` | State | Waiting on reporter |
| `ready-for-agent` | State | Fully specified for AFK agent |
| `ready-for-human` | State | Requires human implementation |
| `wontfix` | State | Will not be actioned |

Every issue needs exactly one state label and one category label.

## State Machine

| Current | Can transition to | Trigger |
| ------- | ----------------- | ------- |
| `unlabeled` | `needs-triage`, `ready-for-agent`, `ready-for-human`, `wontfix` | Skill or maintainer |
| `needs-triage` | `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix` | Maintainer via skill |
| `needs-info` | `needs-triage` | Skill detects reply |

## Workflow: Show What Needs Attention

Query GitHub and present summary grouped into: unlabeled issues, needs-triage issues, needs-info with new activity. Show oldest first.

## Workflow: Triage a Specific Issue

1. Gather context: read full issue, comments, labels, explore codebase
2. Present recommendation: category + state with reasoning
3. Bug reproduction attempt (if bug)
4. Domain-model session if needed
5. Apply outcome: post brief, close, or move to needs-info

## Workflow: Quick State Override

When maintainer explicitly says "move #42 to ready-for-agent", apply labels directly. Skip domain-model session.
